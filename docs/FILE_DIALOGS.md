# 文件选择窗口：v1.28.5

用户报告“地点与构造 → 导入”偶发无法点击文件或文件夹，只能取消、重启软件。旧代码在选择文件时没有防重入，原生对话框也未传入所属主窗口。实际 renderer/IPC 复现中，同一次连续导入发出了两个原生窗口请求，两次的 owner 均为空；证据位于全局 `验证/v1.28.5/baseline/baseline.json`。

`electron/file-dialogs.js` 将文件与文件夹选择、工程打开/保存、文本与 GMT 脚本保存等原生窗口绑定到发起 IPC 的 BrowserWindow。依据 [Electron dialog API](https://www.electronjs.org/docs/latest/api/dialog)，macOS 会将其显示为所属窗口的 sheet。一个原生文件窗口未关闭时，不再创建第二个；关闭所属窗口、正常取消或异常返回均释放占用，较早请求的迟到返回也不会解除新的窗口占用。

地点与构造的导入按钮在选择文件时即禁用，并保护选择、解析、添加的整个过程；本地构造库同步文件夹采用相同保护。原生选择窗口和解析任务分别结束后恢复状态。用户取消或遇到坏数据时可直接重新导入，不增加解释性 UI。

## 验证范围

- `tests/file_dialogs.test.js`：所属主窗口、文件/保存窗口互斥、取消、异常重试、窗口关闭和迟到返回。
- `tests/file_dialog_integration.cjs`：真实 renderer/IPC 流程，连续导入防重入、文件/文件夹窗口不重叠、取消后重开、原生错误和解析错误后的重试、真实 GeoJSON worker 导入与去重。
- `tests/file_dialog_native.cjs`：真实 macOS 原生窗口，在隔离工作区浏览嵌套文件夹、选择 GeoJSON、反复导入/取消、同步构造文件夹，并在文件窗口打开期间创建和关闭生产绘图所用的隐藏窗口。控制器仅操作该 QA 进程的 fixture 文件，不操作用户工程。

源码修复阶段 7 次实际原生选择操作全部完成，得到两个可编辑图层和一个本地构造库要素。原生测试单独采用可见 QA 窗口；现有隐藏工作台检查继续使用不可聚焦窗口。本轮未验证 Windows 的系统原生窗口。

已安装版本再次完成 7 次真实 macOS 选择操作，两组共 14 次。候选包通过 renderer/IPC 错误恢复检查；26 组 Node 回归通过。控制器为 `tests/file_dialog_native_driver.py`，将隔离工作区路径作为参数传入即可控制该 QA 进程。

用户的偶发“列表只能取消”未被稳定重现；本轮直接确认并修复了无所属窗口与重复请求的缺陷，并用上述真实交互验证修复后的选择流程。v1.28.5 已安装至“实用app”并正常启动。发布包及实装验收记录在 `PROJECT_HANDOFF.md` 与全局 `验证/v1.28.5/`。
